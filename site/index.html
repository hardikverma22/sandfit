Sandbox on.Work goes on.

sandfit reads what Claude Code or Codex already did on your machine and writes sandbox rules that allow exactly that. Nothing more.

See what would break. Reads only, changes nothing.npx sandfit
Write the rules into Claude Code's settings. Asks first.npx sandfit apply

Free and open source. Needs Node.js 20 or newer. Your history never leaves your machine.

How it takes the measurements

Everything happens on your machine, from the transcripts Claude Code and Codex already keep.

  1. Read what your agent did

    Every shell command, file edit and web fetch in your recent Claude Code and Codex sessions for this project.

  2. Work out what each one needs

    pip install needs pypi.org and ~/.cache/pip. next dev needs a local port. A knowledge base of common tools fills in what a command's text doesn't say.

  3. Cut the rules to fit

    Narrowest grants that cover it: the cache folder, not your home. Secrets and the agent's own settings are never granted, even if your history touched them.

  4. Test them on history they never saw

    The rules are built from your older sessions and replayed against your newest ones. You see what would still break before anything changes.

  5. Write them, with a backup

    sandfit shows every change, asks first, merges with your own settings and keeps the old file. Then turn the sandbox on.

Inside the line, and outside it

The rules allow what your work needs. Some things stay outside even if your history touched them, because a command that can reach them can do real harm.

Allowed, because you used it

Sites

  • registry.npmjs.org
  • github.com
  • pypi.org
  • api.vercel.com

Folders

  • your project
  • ~/.npm
  • ~/.cache/pip
  • ~/.cache/ms-playwright

Run outside the sandbox, still asking you first

  • docker
  • git pushuses your keys

Never allowed

  • ~/.ssh
  • ~/.aws
  • .env
  • *.pem
  • ~/.claude/settings.json
  • ~/.zshrc
  • .git/hooks

Keys and tokens, the agent's own settings and memory, and files that run code later. If a tool really needs one (npm reads ~/.npmrc), sandfit leaves just that file readable and tells you why.

One history, every sandbox

The same measurements, written in the format your sandbox reads.

Claude Code
npx sandfit apply
Merged into .claude/settings.json, or your user settings with --user.
Codex CLI
npx sandfit apply -t codex
Folders and network in ~/.codex/config.toml. Per-site rules with --codex-profile.
sandbox-runtime
npx sandfit apply -t srt
~/.srt-settings.json, then srt claude.
nono
npx sandfit apply -t nono
A profile, then nono run --profile sandfit -- claude.
NVIDIA OpenShell
npx sandfit emit -t openshell
A policy for openshell sandbox create --policy.
Anything else
npx sandfit emit -t policy
Plain YAML, with how often each rule was needed and an example.

Learn from what got blocked

A script that called an API, a tool that wrote a cache. The sandbox's own errors name them. sandfit lists them and adds only the ones you say yes to, because a blocked attempt can also be an attack.

npx sandfit learn

What it will never do

  • Send your history anywhere

    No network calls, no telemetry. Anything that looks like a token is masked before it's printed or written.

  • Loosen your permissions

    It adds sandbox rules and deny rules for secrets. Allow rules for Claude's own tools only with --with-permissions.

  • Overwrite your settings

    It merges. Your own values win, a backup is kept, and a broken settings file stops it instead of being replaced.

  • Allow broad folders

    Never your home, /, Documents, Downloads, Library, ~/.config or a parent of your project.
